# 相关思维工具（交叉引用）

> 本项目专注五运六气**推算与检索**（算什么、查什么）。隔壁项目 `kangarooking/huangdi-neijing-skill` 把《黄帝内经》素问+灵枢蒸馏成 22 个**思维方法论 skill**（怎么想、怎么决策）。两者互补，形成完整的中医 Agent 能力栈。

## Agent 使用方式

当 Agent 讲解运气概念时，可引用对应的思维工具作为方法论补充：

1. **推算完毕**：用 `calculate_yunqi_api.py` 算出运气格局
2. **检索病机**：用 `rag_search.py` 检索对应病机与医案
3. **思维补充**：引用上表中的关联思维工具，帮用户理解决策思路

> **已自动化（P12）**：`yunqi_report.py` / `personal_yunqi_profile.py` 现在会在「知识库/RAG 章节」之后**自动注入「## 内经方法论」章节**——按当年运气格局（岁运/司天/在泉/体质）自动选取 top-3 内经 skill 并拼装其方法论骨架+边界，无需手动引用。可用 `--no-neijing` 关闭该章节。

> 示例：用户问"今年水运太过该怎么养生？"
> - 本项目给出：水运太过推算结果 + 肾水受邪病机 + 附子山萸汤参考
> - 思维工具补充：`negative-feedback`（亢害承制--水太过则土来制）+ `seasonal-regimen`（四时调养--秋冬养阴）+ `prevention-strategy`（治未病--提前温肾健脾）

## 与对方代码的关系（vendored 快照 vs 完整 skill）

本项目**不复制对方的完整 skill 到运行时**，但为报告「内经方法论」章节之需，已将 22 个 `SKILL.md` 以**只读 vendored 快照**形式纳入 `scripts/lib/neijing_snapshot/`（锁定上游 commit `17106a2`，MIT 可再分发），仅用于抽取其 R/I/A/B 方法论框架，**不附带上游的实时更新与交互式调用**。原因：

1. 上游项目独立维护、仅 1 commit（2026-04-18 AI 蒸馏，无后续维护），快照锁定避免版本漂移与网络依赖（CI 零网络）
2. 两个项目定位不同，合并会模糊各自边界；本仓库只"借用方法论骨架"，不接管其运行时
3. 若需要**完整、可交互**的思维工具能力，仍建议直接安装对方 skill：`git clone https://github.com/kangarooking/huangdi-neijing-skill.git`
